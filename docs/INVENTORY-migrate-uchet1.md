**Проект:** Учёт №1 / Пневмоподвеска

**Дата:** 19.07.2026  
**Роль документа:** зафиксировать, что у клиента уже есть в контуре, что уже делается в Учёте №1, и что можно / нельзя перенести сейчас.

Критерии «можем перенести сейчас»: код и канал данных есть; нет жёсткого блокера (публикация в 1С, железо, внешний API, политика безопасности, cutover DNS/callback).  
Неопределённости помечены **уточнить**.

## 1. Назначение вкладки

Отдельная вкладка для миграционного планирования: **инвентарь систем клиента** + **реестр уже работающего в Учёте №1** + разделение **«можем сейчас» / «пока нельзя»**.

Не смешивать с:
- вкладкой ТЗ Заказчика (`t.0`);
- вкладкой «Не учтено в ТЗ» (каркас gaps);
- вкладкой «Стек» (технологический ландшафт).

Вопрос владельца: что переносим в свою Учёт №1 сейчас, а что ждёт API / публикации / железа / политик.

## 6. Зависимости и порядок переноса

Рекомендуемые волны (не смета, а порядок снятия блокеров).

### Волна 0 — зафиксировать и пользоваться тем, что уже в `1c.*`
- Номенклатура, остатки, приход/расход, сделки, документы PDF, задания, ops, valuation, audit/presence.
- Критерий: команда работает в Учёте №1 как в основном UI склада/CRM-обзора.

### Волна 1 — розничный поток Э1 (без native СДЭК API)
- Дожим заданий iPad, заказ из сделки (замок суммы), СБП, шлюз отгрузки, «Доход»-зеркало.
- СДЭК пока через виджет (ссылка из задания).
- АТОЛ: включить credentials, если договор готов; иначе оставить prepared.

### Волна 2 — деньги под единый домен
- Перенос SBP/Tochka endpoints и Sheets-cron логики под `1c.*` (или reverse-proxy с тем же origin).
- Перепись webhook/callback → cutover `bank.*` → 301.
- Параллельно: инвентарь и отказ `1cpodveska` (**уточнить** hostname).

### Волна 3 — СДЭК native + фискализация в потоке
- E1-7: накладная / трек / ярлык из Учёта.
- Live АТОЛ + контроль ОФД в UI.

### Волна 4 — аналитика v1
- Синк звонков Amo → журнал; экраны `/analytics/*`.
- Внешний Roistat не отключать.

### Волна 5 — склад Э4 / маркировка Э5 / МП Э3 / СТО Э2
- По приоритету бизнеса; каждый блок со своим блокером (железо, ЦРПТ, API МП).

### Жёсткие зависимости
- Native СДЭК ← до сверки наложек МП.
- ЦРПТ ← стабильные партии/скан (Э4 → Э5).
- Cutover bank ← стабильные callback на `1c.*`.
- 2FA ← политика исключений для shared iPad (иначе блок операционки).
- Заказы поставщикам ← публикация в 1С/OData или HS.

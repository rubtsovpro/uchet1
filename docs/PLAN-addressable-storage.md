## 0. Цель

Кладовщик знает не только «на Складе Москва», а **в какой ячейке** лежит деталь. Сборка `/pick` подсказывает адрес. Импорт из таблицы «Март. Ячейки» — стартовое размещение.

Вместимость ячейки («сколько штук влезет») — **отдельный слой** после базового адреса (см. §5).

## 1. Модель данных (минимум)

| Сущность | Суть |
|----------|------|
| `warehouse_cells` | Ячейка: `id`, `warehouse_id`, `code` (`A7.1`), опционально зона/ряд/полка, `is_active` |
| На `product_units` | `cell_id` (nullable) — где лежит **этот** экземпляр |
| Баланс по адресу (qty без марки) | `stock_cell_balances`: `warehouse_id + cell_id + product_id + qty` **или** выводить из units, если всё серийное |

**Правило:** qty на складе = сумма по ячейкам (или «без адреса»). Не ломаем текущий `stock_balances` — ячейка уточняет размещение.

Опционально позже на ячейке:
- `length_cm`, `width_cm`, `height_cm`, `max_weight_g` — для расчёта вместимости;
- `max_sku_qty` — ручной лимит «в эту ячейку не больше N».

## 2. Этапы

### Этап A — справочник + импорт (1 спринт)

1. Таблица `warehouse_cells`, UI: Склад → Ячейки (код, склад, активна).
2. Парсер кода `А7.1` / `A7.1` → нормализация латиница/кириллица.
3. Импорт из Google «Март. Ячейки» (лист актуальный):  
   SKU → product, qty, cell → создать ячейки + записать размещение (qty-баланс или привязка units, если марки однозначны).
4. Отчёт «Остатки по ячейкам» (как лист таблицы).

**Критерий:** по Москве видно SKU в `A7.1` как в таблице.

### Этап B — операции (1–1,5 спринта)

1. Приёмка `/in/scan` (или задание inbound): после скана марки — **скан/выбор ячейки** («положить в…»).
2. Перемещение между ячейками (внутри склада): документ или быстрый скан «из → в».
3. `/pick` · задание на СТО / отгрузка: в карточке строки показать **ячейку(и)**; «Сделал» списывает с ячейки.
4. Инвентаризация по ячейке (опционально в том же этапе): задание «пересчитай A5.2».

**Критерий:** приход без ячейки нельзя закрыть на основном складе (или мягкий режим «без адреса» с флагом).

### Этап C — подсказки и жёсткость (0,5–1 спринт)

1. Рекомендация ячейки при приёмке: «этот SKU уже лежит в A7.1» / пустая соседняя.
2. Запрет отгрузки с «чужой» ячейки, если адрес обязателен.
3. Синхронизация снэпшота из Sheets по кнопке (пока ведут таблицу параллельно).

### Этап D — вместимость (после A–B, когда есть габариты ячеек)

См. §5. Не блокирует адресный учёт «где лежит».

### Вне скоупа MVP

- ТСД-прошивка, RFID, 3D-карта склада, автоназначение оптимального адреса (slotting AI).

## 4. Импорт из «Март. Ячейки»

Формат листа: `Номенклатура | Поставка | Финальный остаток | Ячейка`.

Алгоритм:
1. Нормализовать код ячейки (`А`→`A`).
2. Найти product по SKU.
3. Upsert cell на складе «Склад Москва» (или выбранный контур).
4. Записать qty в cell-баланс; если по SKU ровно N марок `in_stock` без cell — разложить по N (осторожно при расхождениях qty vs units).
5. Расхождения (SKU нет в Учёте, qty≠маркам) → отчёт импорта.

Снэпшоты по датам **не** хранить все — берём последний актуальный лист; история остаётся в Google.

## 5. Сколько товаров влезет в ячейку?

Нужны **две стороны** измерения.

### 5.1. Габариты товара (упаковки)

Уже в Учёте на номенклатуре:
- `package_length_cm`, `package_width_cm`, `package_height_cm`
- `package_weight_g`

Без трёх сторон упаковки автоматический расчёт **невозможен** (только ручной лимит).

**Факт на проде (2026-08-07):** из ~18 700 товаров полное `L×W×H` упаковки заполнено у **~1 120** (~6%), вес — у ~1 100. Перед вместимостью — дозаполнение габаритов.

### 5.2. Габариты / лимиты ячейки

Сейчас в таблице ячеек **нет** размеров полки — только код. Нужно завести на ячейке хотя бы одно из:

| Поле | Зачем |
|------|--------|
| `length_cm × width_cm × height_cm` | объём ячейки |
| `max_weight_g` | не перегрузить полку |
| `max_qty` (опционально) | жёсткий лимит «не больше N шт» без геометрии |
| Допуск / коэффициент заполнения (0.7–0.85) | воздух, ориентация, разные SKU |

### 5.3. Формула (простая, MVP)

Для **одного SKU** в ячейке (одинаковые коробки):

1. Объём товара: `Vt = L×W×H` (см³).  
2. Объём ячейки: `Vc = Lc×Wc×Hc × fill` (fill ≈ 0.8).  
3. По объёму: `Nvol = floor(Vc / Vt)`.  
4. По весу: `Nw = floor(max_weight_g / package_weight_g)`.  
5. Итог: `N = min(Nvol, Nw, max_qty?)`.

Уточнения (позже):
- ориентация коробки (перестановка L/W/H → max N);
- несколько SKU в одной ячейке — сумма объёмов/весов уже лежащего + нового;
- «плоская» укладка vs «столбик» — без этого Nvol завышен.

### 5.4. Практичный старт без геометрии ячеек

Пока размеры полок не замерили:
- вести только **адрес** (где лежит);
- для популярных ячеек вручную `max_qty` по факту («в A7.5 больше 15 не ставим»);
- параллельно дозаполнить `package_*` у номенклатуры и обмерить ряд/полку раз в жизни.

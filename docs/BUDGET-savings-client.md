# Экономия · контур клиента

**Проект:** Учёт №1 / Пневмоподвеска  
**Дата:** 2026-07-19  
**Роль:** план действий — что режем, что автоматизируем, чем обосновываем сокращение штата склада  
**Связанные вкладки:** «Роадмап · можем сейчас», §6 Склад, §8 Деньги, §13 Персонал, §16 Аналитика, §17 Интеграции

---

## 1. Назначение

1. Зафиксировать **текущий расход** по сервисам и людям (как назвал Заказчик).  
2. Показать **что делать**: решения сходу, замена SaaS, cutover с 1С, сокращение штата склада через автоматизацию.  
3. Отделить **опасно резать до cutover** (РАРУС/1С-облако, Roistat) от **заменяемого** (Квазар, i2crm, A5) и от **решения «не нанимать»** (программист 1С).  
4. Зафиксировать **бюджет развития / автоматизации с Исполнителем = 200 тыс. ₽** (не Дробот-ежемесячно).  
5. Не путать **разовое** (Дробот 150 за авито-сообщения) с **ежемесячным**.

Логика экономии: (а) не уводить бюджет в доработки 1С; (б) отключить SaaS после замены в Учёте/боте; (в) сократить ФОТ склада/офиса за счёт Э1 + КПД по таймингу задач.

|---|--------|--------|-----|-------------|

| 3 | Квазар «Автопоиск» (VIN для авито-бота) | 35 | ежемес. | VIN → бот Авито |

**Сумма «видимого» ежемесячного контура (без потолка автоматизации как burn):**  
1+2+3+4+5+7+Аня ≈ **449** тыс. ₽/мес (если программист 1С учитывается как резерв).  
Без резерва 1С-программиста: **~299** тыс. ₽/мес сервисы + офис/склад (Аня как ориентир).

### Уточнения

- **Дробот 150** — разовая настройка авито-сообщений («и всё»). Не закладывать как 150/мес.  
- **Автоматизация 200** — потолок на развитие с Исполнителем. Цифра «1 200» в переписке — ошибка/опечатка Заказчика; **изначально имелось в виду 200**. Это не «экономия −1 000 от потолка 1 200».  
- **Программист 1С 150** — не ФОТ сейчас; решение «не нанимать» = не уводить деньги в доработки 1С, а в пакеты Учёт №1.

## 3. Решения сходу и near-term

Условие: решение Заказчика + закрытие функции в Учёте №1 / боте Исполнителя. Цифры — **тыс. ₽/мес**.

| Статья | Экономия | Что делать | Риск |
|--------|----------|------------|------|
| **Программист 1С (бюджет)** | **150** | **Решение: не нанимать.** 1С точно убираем с горизонта развития: критичные правки УНФ — точечный подряд до cutover; все доработки → Учёт №1. Cutover с РАРУС — когда Учёт закрывает ядро (номенклатура, остатки, отгрузки, деньги) | Если срочно нужна доработка УНФ до cutover — подряд, не FTE |
| Квазар «Автопоиск» | **35** | VIN/каталог в контуре бота или Учёта (свой справочник / API) | Пауза бота Авито на период миграции |
| i2crm (Telegram/Max → CRM) | **36** | Свой мост: Telegram/Max → Amo (или ingest в Учёт → Amo) | Пропуск лидов в дни cutover |
| A5 Client | **10** | Ответы/очередь авито-сообщений в боте или Учёте (после разового Дробот — не плодить второй SaaS) | SLA ответа на Авито |
| **Итого near-term (решения + замена SaaS)** | **~231** | Строки 1+3+4+7 | Без штата склада и без Roistat/РАРУС |

**Сходу по деньгам «сегодня» (без разработки замены):** **150** — не нанимать программиста 1С.  
**потолок автоматизации 200** — фиксируем как целевой бюджет развития; **не считаем** отдельной строкой «экономии от 1 200».  
**Сходу по сервисам после 2–6 недель работ Исполнителя:** +**81** (Квазар+i2crm+A5), если приёмка замены пройдена.

### 1С — решение и roadmap

| Шаг | Действие |
|-----|----------|
| Сейчас | **Не нанимать** программиста 1С (150). Бюджет → Учёт №1 (Э1, замена SaaS, КПД склада) |
| До cutover | РАРУС (38) **держим**: master ещё в 1С; Учёт синхронизирует |
| Cutover | Когда Учёт №1 закрывает ядро операций — план отключения РАРУС совместно с Заказчиком; точечный подряд 1С только на миграцию/закрытие, не на развитие |

## 5. Сокращение кладовщиков / Аня — что автоматизировать

**Решение Заказчика:** убирать не «только Аню 100к», а **количество кладовщиков / офис-операционку** за счёт автоматизации. Аня — ориентир роли, не единственная статья.

Цель: меньше ручных рук на розничных отправках — очередь заданий, шлюз оплаты, выдача со сканом.

### Типовые задачи → замена в Учёте №1

| Задача сейчас (типично) | Замена в Учёте №1 | Этап |
|-------------------------|-------------------|------|
| Собрать/проконтролировать отгрузку | Очередь **заданий склада** (iPad): собрал → упаковал → к выдаче | Э1 |
| Выдать курьеру / отметить передачу | **Скан выдачи**, списание, статус | Э1 |
| Не отгрузить без оплаты | **Шлюз оплаты**: выдача только если оплачено или канал постоплаты | Э1 |
| Заказ из сделки, сумма «как договорились» | Кнопка **заказ из сделки** + **замок суммы** | Э1 |
| Ссылка на оплату клиенту | **СБП / оплата** из заказа | Э1 |
| Запись в «Доход» / контроль дня | Лента **Доход** + `/ops` | Э1 / Э1+ |
| СДЭК-накладная «вручную» | Виджет из задания; native — после ключа | Э1 → Э1+ |
| Статусы «где заказ», зависли на сборке | Статусы + дашборд дня + **тайминг этапов** (§6) | Э1+ |

### Честно

- Сокращение штата = **не «выключить завтра».** Нужны приёмка Э1 (пилот недели) и дожим Э1+ (каналы: наложка, самовывоз, автобус, свой курьер).  
- На период пилота: дежурство на эскалациях — иначе риск срыва отгрузок.  
- Экономия по ФОТ (Аня **и/или** ставка кладовщика) — после стабильной недели и **цифр КПД** (§6), не в день старта разработки.

## 6. Автоматизация + КПД по таймингу задач склада

Зачем: автоматизация Э1 снимает рутину; **тайминги** дают Заказчику основание сократить штат (сколько минут на задание, где узкое место, сколько FTE реально нужно).

### Что измерять (KPI / КПД)

| Метрика | Смысл |
|---------|--------|
| Время до взятия в работу | created → picked |
| Время сборки | picked → packed |
| Время до выдачи | packed → handed |
| Полный цикл задания | created → handed |
| Очередь / просрочка | задания старше N минут; пики по часам/дням |
| Нагрузка на роль | заданий / человек / смена |

### Что сделать в Учёте №1

1. На `warehouse_tasks` — метки времени этапов: **created → picked → packed → handed** (и отказ/эскалация при необходимости).  
2. Отчёт / экран КПД: среднее и P50/P90 по этапам, по дням, по сотруднику/роли (без лишней «слежки» — для обоснования штата и узких мест).  
3. Связка с приёмкой Э1: пилот «неделя» сравнивает объём отгрузок и тайминги **до/после**; решение по сокращению кладовщиков / Ани — по факту отчёта.

бюджет автоматизации 200 может поддерживать подсказки по статусам и разбор эскалаций — **не вместо** шлюза оплаты и очереди iPad.

## 7. Бюджет развития / автоматизации: 200 тыс. ₽ с Исполнителем

| Параметр | Значение |
|----------|----------|
| Потолок | **200** тыс. ₽ / мес на развитие с Исполнителем |
| Не путать | Дробот 150 — **разово** (авито-сообщения), не ежемесячная подписка |
| Уточнение | «1 200» в переписке — опечатка; целевой потолок всегда **200**. Не вести учёт «экономии −1 000» |

### Куда тратить 200 (приоритет)

1. **Авито / сообщения** — стабильный автоответ и очередь без второго SaaS.  
2. **Склад / Э1** — сценарии заданий, подсказки по статусам, меньше ручных эскалаций.  
3. **CRM-операционка** — черновики ответов / разбор лидов после замены i2crm (не вместо шлюза оплаты).  
4. **Не тратить** на «ещё один Дробот» и на полный «свой Roistat» из бюджета автоматизации — аналитика звонков идёт отдельным §16.

## 8. Итого по горизонтам

| Горизонт | Экономия, тыс. ₽/мес | Что входит |
|----------|----------------------|------------|
| **Сходу (решения)** | **150** | Не нанимать 1С-программиста; потолок автоматизации зафиксирован **200** (не строка «−1 000») |
| **1–2 мес (замена SaaS)** | **+81** → суммарно **~231** | Квазар 35 + i2crm 36 + A5 10 |
| **После пилота Э1 + КПД** | **+100+** → ориентир **~331+** | Сокращение кладовщиков / Аня — по факту таймингов |
| **После cutover с 1С** | **+38** → суммарно **~369+** | РАРУС |
| **После аналитики / решение по Roistat** | **+80** → до **~449+** | Roistat — когда свой контур закрывает звонки+рекламу |

**Ориентир burn после near-term (1–2 мес, штат ещё на месте):** сервисы+офис ≈ **299 − 81 = 218** тыс. ₽/мес (+ автоматизация до 200 по факту работ).  
**Ориентир после Э1 и сокращения штата (уровень Ани):** ≈ **118** тыс. ₽/мес до отключения РАРУС/Roistat — уточнять по КПД и фактическому ФОТ.

## 9. Рекомендуемый порядок действий

1. ☐ **Решение:** программист 1С **не нанимается**; 1С убираем с горизонта развития (критичное — подряд; развитие — Учёт №1).  
2. ☐ Зафиксировать **потолок автоматизации 200** с Исполнителем; Дробот не переводить в ежемес.  
3. ☐ Спека замены **i2crm** + дата отключения.  
4. ☐ Спека замены **Квазар** (VIN) + дата отключения.  
5. ☐ Спека **A5 / авито-сообщения** — один контур, без дубля SaaS.  
6. ☐ Не трогать **РАРУС** и **Roistat** до критериев §4; roadmap cutover РАРУС — когда ядро в Учёте.  
7. ☐ Дожать Э1: задания (iPad) → выдача → шлюз оплаты → Доход.  
8. ☐ **КПД:** timestamps на `warehouse_tasks` (created → picked → packed → handed) + отчёт; пилот недели.  
9. ☐ По отчёту КПД — решение по **сокращению кладовщиков / Ани**.  
10. ☐ Параллельно: аналитика A1 (§16); решение по Roistat — отдельно, не из бюджета автоматизации 200.

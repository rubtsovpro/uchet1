## 20.07.2026 — внутренние чаты сотрудников

- Раздел **`/chats`**: личные DM и группы между сотрудниками (как Telegram lite).
- Текст, reply, пересылка; фото/документы → **S3 private** (`chat/{chatId}/{msgId}/…`), скачивание только участникам чата.
- Polling 2–3 с, badge непрочитанных в боковом меню; раздел прав `chats` (роли + матрица).
- Вне scope: видеозвонки, клиентские каналы (Wazzup / tg-amo-bridge).

## 19.07.2026 — вечер · экраны слесарей / СТО (дополнение)

Только новое по контуру СТО и ролевым экранам. Без дублей дневной сводки.

### Подъёмник `/lift`
- Экран мастера на подъёмнике: открытие смены (PIN), текущее задание / заказ-наряд, материалы по ЗН, статусы авто на посту.
- **Учёт работ по слесарю:** фиксация работ исполнителя (`sto_work_logs`) — кто что сделал по заказ-наряду, время на подъёмнике.
- Роль/раздел `lift` · `works`; home мастера СТО → `/lift`.

### Приёмщик `/reception`
- Экран приёмщика: **ожидаемые авто на СТО сегодня** (записи / статусы: ожидается → прибыл → на подъёмнике → готово).
- Роль/раздел `reception` · `works`; путь `/reception` (также `/sto/reception`).

### Поддомены и быстрый вход
- Ролевые хосты под `uchetn1.ru`: `pick.` · `photo.` · `lift.` · `in.` / `reception.` — Apache ServerAlias + host→landing на VPS готовы; staff на apex.
- На полном WMS (`uchetn1.ru` / `1c.pnevmopodveska1.ru`) — home по роли (кладовщик → `/pick`, фотограф → `/photo`, СТО → `/lift`).
- **DNS:** A для `@`/`www` есть; A для pick/photo/lift/reception/in — **ещё нет** → HTTPS expand ждёт dig. См. `deploy/DNS-uchetn1.md`.

### Помощь / роли
- `/help`: четыре карточки → `https://pick|photo|reception|lift.uchetn1.ru` (не относительные `/pick` …).

## 19.07.2026 — вечер (дополнение к журналу)

## 19.07.2026 — отчёт за день (день / вечер)

Полный срез работ за сутки. Ниже — сводка по блокам; детализация также в таблице журнала.

### Медиа и данные
- Media-full-sync **остановлен** (процесс + cron), затем **перезапущен догрузка фото из 1С**: режим onlyMissing, файлы **>220 MB пропускаются**.
- По блокам «долги нам / поступления»: без опубликованного OData из 1С живые остатки/взаиморасчёты не подтянуть — нужен доступ к каталогам/документам OData на стороне 1С.

### Меню и навигация
- СДЭК убран из «Закупки» → блок «Доставка» под «Склад».
- Чистка «Закупки»: сняты заглушки, отчёты-заглушки, ссылки sync 1С; «Виды цен» не в закупках.
- Карта меню / паритет MAP: **308 → 306** пунктов; **0 «нет»**, ~100% «есть» + «частично» (тонкие журналы).

### Персонал и доступ
- Staff: админ `rubtsov` для разработки; **системный admin** — отдельно (не смешивать).
- 2FA через Telegram (`finpnevmo_bot`): **включали**, затем **отключили по запросу** — коды входа больше не уходят; вход снова по паролю. Health: `auth_2fa.mode=off`, `ready=false`. Платёжный бот bank не трогали.

### Деньги и оплата
- Валюты RUB / USD / CNY + курсы ЦБ на проде; в шапке отображение курсов **$ / ¥**.
- СБП poll + KPI склада `/warehouse/kpd` (метки этапов, avg/P50/P90).
- Ссылка оплаты `/pay/{token}`: QR СБП + карта (stub), таймер, резерв «Ожидание оплаты».

### UI / бренд
- Единый формат телефонов + настройки вариантов (`/settings/phones`).
- Иконки сайдбара (CSS-фикс скрытия) + тултипы секций.
- Брендбук: лого «квадрат + 1», тёмная схема; фикс лого on-dark (XML); **`vision.html` снят с веба** (404) — оффер только в Google Doc и `docs/VISION-uchet1.md`.

### Складские экраны / автоматизация склада
- `/pick`: список заданий, срочность, типы, тема, смена, без «Полный UI», кнопка «Обновить · время».
- Очередь / сделал / не сделал+причина → следующее; role-gate warehouse/courier → `/pick`.
- Задания склада, ops-дашборд, КПД — контур автоматизации склада на проде.

### Документы и оффер (вкладка «Моё виденье»)
- Цифры: ориентир **480 тыс. ₽/мес**, работа из **МСК**; недели **1–3** — запуск складских экранов / автоматизации склада; поддержка **371 тыс. → снижение с 3-го месяца**; счета **49–55** (что теряет актуальность при переходе на Учёт №1).
- Опыт внедрений: НГ Энерго / Экомир / Лаком / Атаска / Робито.

### Интеграции
- СДЭК: native keys найдены; bridge трек / ярлык в WMS.
- Каркас `tg-amo-bridge` (личный Telegram менеджера ↔ amo) — цель заменить Wazzup ~**38 тыс. ₽/мес**.
- Организации: multi-org справочник + поле на продажах / складе / ссылке оплаты.

### Отчёты

- Веб-1С РАРУС (`.vrd`) — **сломан**, на него не опираемся.

## Что осталось — полный бэклог Учёт №1

Фактический остаток по `docs/` (ROADMAP · VISION · SMETA · MAP · §1–§18 · NEXT-BATCH · PAYMENT-LINK · INVENTORY). Меню MAP: **~306** пунктов, **0 «нет»**, основная доля — **«частично»** (тонкие журналы без глубины UNF). Не полный паритет УНФ. ## Роли

Практический набор ролей для эксплуатации Учёт №1 (операции склада, закупок, продаж, денег, СТО и доставки). В системе роль задаётся в **Персонал**; поверх роли можно уточнить разделы и флаги. Ниже — кто что делает и куда заходит.

### 1. Кладовщик
**Что делает:** открывает смену (PIN), берёт задания на сборку / отгрузку, отмечает «сделал» или «не сделал» с причиной, двигает очередь склада без офисной диспетчеризации.  
**Ключевые экраны:** `/pick` · `/warehouse/ops` · `/warehouse/today` · `/warehouse/tasks` · `/warehouse/kpd` (КПД смены).  
**В системе:** роль `warehouse` (кладовщик); при «только сборщик» — home → `/pick`.

### 2. Фотограф
**Что делает:** снимает номенклатуру с остатком без фото, загружает кадры в каталог (S3 / `product_media`), закрывает очередь «склад без фото».  
**Ключевые экраны:** `/photo` · `/media/photos` (фильтр «есть остаток, нет фото»).  
**В системе:** обычно узкий доступ к складу / медиа; карточка на `/help`.

### 3. Закупщик
**Что делает:** ведёт поставщиков и приходные, готовит заказы поставщикам (когда доступны в 1С/OData), следит за сроками поставки (`lead_time_days`), ГТД, потребностями и ценами закупа.  
**Ключевые экраны:** раздел **Закупки** · `/purchases` · `/in` (приходные) · поставщики · `/api/gtd` / UI ГТД по мере готовности.  
**В системе:** доступ к разделу `purchases` (+ при необходимости склад для приёмки).

### 4. Менеджер продаж / CRM
**Что делает:** ведёт сделки и клиентов, выставляет счета / УПД / заказ-наряды, связывает оплату и выдачу, работает с контуром AmoCRM (сделки → задания складу).  
**Ключевые экраны:** **CRM** · **Продажи** · `/sales/invoices` · `/sales/upd` · покупатели · карточка сделки · события CRM.  
**В системе:** роль `sales` (продажи) или `manager` с разделами CRM/продажи.

### 5. Кассир / деньги
**Что делает:** принимает оплаты (СБП QR сейчас; эквайринг и касса АТОЛ — по готовности ключей), контролирует статусы платежей и чеков, не путает предоплату и полный расчёт.  
**Ключевые экраны:** ссылка оплаты `/pay/{token}` · настройки `/settings/payment-link` · раздел **Точка / Деньги** · журнал продаж с оплатой.  
**В системе:** доступ к `money` / продажам; АТОЛ live — после credentials.

### 6. Администратор
**Что делает:** заводит персонал, назначает роли и разделы, PIN для смен `/pick`, пароли, настройки интеграций (СДЭК, АТОЛ, Точка), синхронизацию 1С, организации и телефоны.  
**Ключевые экраны:** **Персонал** · **Настройки** · `/settings/*` · `/organizations` · `/settings/phones` · `/delivery/cdek/settings`.  
**В системе:** роль `admin` (полный доступ).

### 7. Руководитель / аналитика
**Что делает:** смотрит отчёты и KPI (продажи, динамика, склад, КПД), без операционной правки документов; принимает решения по остаткам и деньгам.  
**Ключевые экраны:** **Главное** · KPI · `/warehouse/kpd` · анализ продаж · дашборды (по мере live vs stub).  
**В системе:** роль `manager` / `readonly` (наблюдатель) — преимущественно чтение.

### 8. Курьер / логист (СДЭК)
**Что делает:** забирает собранные отправления, работает с доставкой СДЭК (журнал сделок, трек, ярлык; native накладная из Учёта — в дорожной карте), при необходимости видит задания выдачи.  
**Ключевые экраны:** `/delivery/cdek` · `/delivery/cdek/settings` · при пилоте — пересечение с `/pick`; отдельный экран курьера — в бэклоге.  
**В системе:** роль `courier`; сейчас часто стыкуется со складским контуром.

### 9. Мастер СТО / приёмщик / слесарь
**Что делает:** принимает авто на день (`/reception`), ведёт пост на подъёмнике (`/lift`): задание, материалы ЗН, учёт работ по слесарю; касса мастера (нал / терминал / QR + чек) — по волнам СТО.  
**Ключевые экраны:** `/lift` · `/reception` · раздел **Работы / СТО** · заказ-наряды · календарь / посты (глубина — в бэклоге).  
**В системе:** роль `sto`; разделы `lift` / `reception` / `works`.

### 10. Бухгалтер (опционально)
**Что делает:** контролирует документы продаж и закупок, сверки, дебиторку/кредиторку, печатные формы; исходящие платежи — только после approve владельца.  
**Ключевые экраны:** журналы документов · деньги / Точка · продажи / закупки (чтение или правка по политике).  
**В системе:** роль `accountant`.

# Пакет документов СТО (ТО и ремонт АМТС)

Источник: Правила оказания услуг по ТО и ремонту АМТС (ПП РФ № 780 от 29.05.2025) + бланки заказчика.  
Шаблоны: `api/assets/sto-templates/` (DOCX + TXT). Каталог в API: `GET /api/sto-doc-templates`.

## Редактор бланков (макросы)

**UI:** [Настройки → Шаблоны документов](https://uchetn1.ru/settings/doc-templates)  
**Папка Drive:** [Шаблоны документов СТО](https://drive.google.com/drive/folders/1jjmTeuMnTxH5V9I-WPSR97m43nMFBsY1) — внутри отдельно:

- [Роман · ИП Безматерных Р.П. (Москва)](https://drive.google.com/drive/folders/1956qDpuVuSBGskaSm1ba8PyTcgcLq9tZ)
- [Михаил · ИП Безматерных М.П. (Краснодар)](https://drive.google.com/drive/folders/1GgeU06gG571JnIVAB0E5vJIKAtj1BCEA)

В каждой папке: клиентские **01 / 02 / 03ф / 03ю / 10 / 11** + служебные **13 приказ / 14 регламент / 15 чек-лист**.  
У Романа **02** = договор юрлица МСК (поставка и ремонт, текст юриста). У Михаила **02** = рамочный СТО.  
В печати: продавец ИНН `231215603728` (Роман) → шаблон `sto-contract-legal-msk`; иначе юр. клиент → `sto-contract-legal`. Перечень ТС и представителей — в заказ-наряде / иных бланках, отдельный 02а не печатаем.

После правок в Drive шаблоны подтягиваются при печати PDF (TTL ~10 мин, кэш `api/assets/sto-templates/cache/{roman|mikhail}/`). Кнопка **«Подтянуть»** в настройках — принудительный sync по `by_owner` манифеста.  
Манифест: `docs/sto-templates/gdrive-sto-edit.json`.  
**Источник правды текста** = Google Drive (папка ИП по ИНН продавца). Локальный TXT — кэш/fallback. В хабе «Документы» строка «Бланки: Google Drive / кэш / локальный».

### Печать из заказа

| Endpoint | Что |
|----------|-----|
| `GET /crm/deals/:id/sto-pack.pdf` | Полный пакет (договор + ЗН ×2, ПДн ×1 для физлица). Текст с Drive + печать/подпись. Помечает ЗН как распечатанный. |
| `GET /crm/deals/:id/sto-pdn.pdf` | Только согласие ПДн |
| `GET /crm/deals/:id/sto-extra/:templateId.pdf` | Доп. бланки из Drive: акт о неявке, чек-лист |
| `GET /sales-docs/:id/pdf` | Договор / ЗН СТО — тот же Drive→PDF (не операционный ЗН) |

Параметры: `organization_id`, `stamps=0`, `signs=0`, `download=1`.  
В хабе «Документы» блок **Доп.Документы** — акты по этапам чек-листа. Приказ и регламент — только в настройках шаблонов (не на каждый заказ).

Перед печатью пакета смотрите блок «Не хватает для бланков» (клиент, СТС/авто, банк у юрлица, мастер-приёмщик). Строки работ/запчастей подтягиваются из заказ-наряда.

## Ключевое правило

**Нет подписанного документа — нет работ.** Автомобиль не принимается в работу до подписания заказ-наряда и приёмо-сдаточного акта.

## Развилка — кто клиент (авто по типу покупателя)

| № | Документ | Когда |
|---|----------|--------|
| 01 | **Договор-оферта для физлица** | Физлицо (личные нужды) → ЗоЗПП + Правила № 780 |
| 02 | **Договор с юрлицом / ИП** (рамочный) | Юрлицо/ИП → рамочный договор + заказ-наряды; наличные ≤ 100 000 ₽; отсрочка — только с разрешения ИП |
| 03ф | **Заказ-наряд для физлица** | Физлицо: единый бланк + акцепт оферты |
| 03ю | **Заказ-наряд для юрлица / ИП** | Юрлицо/ИП: приложение № 1 к рамочному договору |

Выбор 01/02 и 03ф/03ю — по `buyer_kind` / ИНН / юрпризнаку сделки (`suggestStoContractTemplateId` / `suggestStoWorkorderTemplateId`).

## На один заказ (после договора)

| № | Документ | Когда |
|---|----------|--------|
| 03 | Заказ-наряд (операционный бланк с позициями) | **Всегда**; печать с факсимиле печати организации |
| 04 | Приёмо-сдаточный акт приёма авто | **Всегда** вместе с ЗН |
| 05 | Акт осмотра (дефектовки) | Если объём работ не ясен сразу |
| 06 | Акт согласования доп. работ | Неисправность вне ЗН |
| 07 | Акт приёма-передачи запчастей заказчика | Если клиент привёз свои запчасти |
| 08 | Акт сдачи-приёмки выполненных работ | **Всегда** при выдаче после полной оплаты |
| 09 | Гарантийный талон | **Всегда** вместе с актом 08 |
| 10 | Акт о неявке заказчика | Не забирает авто после уведомления |
| 11 | **Согласие на обработку ПДн** | **Только физлицо** на СТО, отдельным бланком (152-ФЗ). У юрлица / ИП не берём. Не вшивать в договор/ЗН. Без отметки в чек-листе ЗН оплата физлица на СТО не открывается |

## Физлицо на СТО — что НЕ собираем

На канале **Автосервис** + тип покупателя **Физлицо**:

- **Не спрашиваем** e-mail, адрес регистрации, паспорт.
- Личность / документ на авто — **СТС** (фото + OCR) и поля авто (госномер, VIN, марка…).
- В UI: `dealStoPersonNoPassportDocs()` — скрывает паспортный блок на заказе, в хабе «Документы» и в карточке договора.
- Счёт (безнал) и УПД без ИНН — не для этого сценария; ПДн — только в PDF пакета физлица.

Юрлицо / ИП / отправка-самовывоз без СТО — свои реквизиты (ИНН, паспорт при необходимости) остаются.

## Единая матрица «кому какие документы»

**Источник правды в UI:** Настройки → **Шаблоны документов**

1. Таблица **бланков** (Клиент / Автосервис / Самовывоз / Доставка) — DOCX и audience.
2. Таблица **пакета по роли и каналу** — что создаётся в заказе (договор / ЗН / ПДн / счёт / УПД). Считает `describeSaleDocPack` / `buildSaleDocPackMatrix` (`deal-sale-rules.ts`).

В **Amo → Правила → Сценарии** колонка «Документы» **только для чтения** (тот же расчёт). Руками не дублировать.

## Служебные (не для клиента)

| Документ | Назначение |
|----------|------------|
| Приказ о введении форм и регламента | Один раз при запуске пакета |
| Регламент мастера-приёмщика и администратора | Пошаговая инструкция персонала |
| Чек-лист приёма и выдачи | Контроль по каждому ЗН |
| 12. Правовая справка | Для владельца / юриста |

## Логика коротко

- Приём физ: договор 01 → **03ф + ПДн**; юр: договор 02 + приложения → **03ю** (без ПДн); акт 04; **05** по необходимости  
- В процессе: **06**, **07** по ситуации  
- Выдача: **08 + 09** всегда; **10** при неявке  

Печать / PDF договоров и бланков СТО — с факсимиле печати организации (скан из `org-stamps` / assets).

В Учёте №1: на заказе — вкладка **«Документы»** (пакет PDF, бланки по роли). Матрица «кому какой» — **Настройки → Шаблоны документов**.

## Чек-лист на заказ-наряде

На карточке **заказ-наряда** — интерактивный чек-лист: галочки с автосохранением. Пункт **«Согласие на ПДн»** обязателен. Полный экран: `GET /api/sales-docs/:id/sto-checklist`.

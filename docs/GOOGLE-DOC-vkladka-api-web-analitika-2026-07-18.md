# Учёт №1 — план: разделение API/Web, единый домен, аналитика / Roistat

Дата дополнения: 18.07.2026

## 1. Цель

1. Разделить код на два пакета в одном репозитории: `api/` (бэкенд) и `web/` (фронт). Общение только через `/api`.
2. Свести весь продукт на один домен: **1c.pnevmopodveska1.ru**.
3. В том же контуре: телефоны контрагентов, АТС МегаФон → Amo, отчёты, коллтрекинг, свой контур аналитики в духе Roistat.

---

## 2. Единый домен (отказ от старых хостов)

| Было | Решение |
|------|---------|
| 1c.pnevmopodveska1.ru | Единственная точка входа: UI + API + аналитика + банк/оплаты |
| bank.pnevmopodveska1.ru | Отказываемся. Точка / СБП / выписки → под 1c.pnevmopodveska1.ru. Старый хост: 301 → затем выключение |
| 1cpodveska (старый контур) | Отказываемся. Пользователи и интеграции → 1c.pnevmopodveska1.ru; потом снятие DNS/хоста |

Правила:
- Cookie-сессия только на 1c.pnevmopodveska1.ru.
- Callback (Точка, Amo ingest, вебхуки) переписать на новый origin до отключения старых хостов.
- Сервер может остаться тот же (VPS); меняется схема vhost/прокси.

## 3. Структура репозитория (цель)

```
warehouse/          # корень проекта
  api/              # Hono + SQLite — только /api/*
  web/              # UI (legacy + React) → web/dist
  docs/             # ТЗ и закладки
  deploy/
```

- api: auth, CRM, склад, оплаты, аналитика, presence, audit.
- web: весь UI; данные только fetch('/api/...').
- Dev: Vite proxy /api → :3101.

## 4. Продуктовые блоки

### 4.1. Телефоны (контрагенты)
- В карточке: Тел 1 / Тел 2, разбор склейки, кнопка «Раскидать».
- В БД одна колонка phone (совместимость с 1С).
- Вид: radio — покупатель ИЛИ поставщик (не оба).

### 4.2. АТС (МегаФон)
- АТС: МегаФон.
- Звонки уже в AmoCRM — основной канал для Учёта №1.
- Прямой API Мегафона — не в v1 (только если Amo не хватает полей).

### 4.3. Коллтрекинг
- v1: журнал звонков из Amo → таблица в WMS, склейка со сделкой/контактом.
- Динамическая подмена номеров как у Roistat — не v1.

### 4.4. Отчёты и аналитика
- Раздел меню «Аналитика» на 1c.pnevmopodveska1.ru.
- Экраны: Обзор, Звонки, Сделки/воронка, Склейка, CSV.
- API: /api/analytics/* 
- Опора на уже есть: /ops, доход-зеркало, сделки Amo, оплаты.

### 4.5. Roistat (свой контур)
- Цель: свой контур в Учёте №1 (звонки + сделки + деньги), параллельно внешнему Roistat.
- v1: операционная аналитика + колл-журнал из Amo.
- Позже: UTM, источники, рекламные кабинеты, полная атрибуция, расширенный коллтрекинг.
- Внешний Roistat не отключать до отдельного решения.

## 6. ТЗ аналитики (кратко для этой вкладки)

### v1 закрывает
- Звонки за день/неделю: кто, пропущенные, длительность
- Связка звонок ↔ сделка ↔ оплата/отгрузка (где есть)
- Сводки по воронкам Amo + ops/доход
- Таблицы + CSV

### v1 не закрывает
- Полная замена Roistat 1-в-1
- Прямой API Мегафона / CDR
- Динамический коллтрекинг с подменой номеров
- UTM / Директ / Авито / мультиканальная атрибуция

### Источник звонков v1
МегаФон → AmoCRM → синк в Учёт №1 (без прямого API Мегафона).

### Экраны
| Экран | URL | Назначение |
|-------|-----|------------|
| Обзор | /analytics | KPI: звонки, сделки, доход, отгрузки |
| Звонки | /analytics/calls | Журнал + фильтры + склейка |
| Сделки | /analytics/deals | Сводки по воронкам |
| Склейка | /analytics/links | Звонок → сделка → оплата/отгрузка |

### Критерии приёмки v1 (сжато)
1. Раздел «Аналитика» в меню — рабочий.
2. Журнал звонков; сверка с Amo за день ≤ 5% расхождения по количеству.
3. ≥ 80% звонков со сделкой или явно «без сделки».
4. KPI на обзоре + склейка + sync по кнопке/cron + CSV.
5. Прямой API Мегафона не используется.

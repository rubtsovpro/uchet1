# Роадмап · рыночная оценка

**Проект:** Учёт №1 / Пневмоподвеска  
**Продукт:** `1c.pnevmopodveska1.ru`  
**Роль:** рыночная стоимость замены УНФ по глубине (не «тонкое меню»), состав команды и календарь 12 месяцев  
**Связанные вкладки:** «Смета · роадмап ответственности», «Моё виденье» (пакет одного специалиста), «Карта 1С УНФ → Учёт №1», §1…§18 реализация, «Экономия · контур клиента»

---

## 1. Назначение

1. Дать **адекватную рыночную оценку** полного scope (§0–§18) с учётом ролей: DevOps, UI/UX, QA, backend, frontend (или fullstack), аналитик/внедренец, поддержка.  
2. Зафиксировать **реалистичные сроки**: карта УНФ ~306 пунктов — это глубина процессов, не список пунктов меню; паритет с УНФ — **месяцы**, не недели.  
3. Развести продукты: **рыночная команда** (эта вкладка) vs **пакет одного специалиста 480 тыс. ₽/мес** (вкладка «Моё виденье»).  
4. Согласовать цифры со сметой (~8,6 млн минимум+год / ~18 млн CAPEX прежней модели) и обновить якорь под полный штат ролей.

## 2. Допущения (рынок РФ, mid-2026)

Ставки — **валовой FTE для клиентской сметы** (не «чистыми» на руки сотрудника), без демпинга.

| Параметр | Значение |
|----------|----------|
| Глубина | Паритет УНФ по процессам склада, продаж, денег, СТО, МП, маркировки — не «экраны-заглушки» |
| Карта меню 1С | **~306–308** пунктов; доля «есть / частично» низкая — остаток = основная работа |

**Пересчёт:** 1 чел-день ≈ 22 / 28 / 35 тыс. ₽ (низ / якорь / верх). Якорь FTE выше — из‑за DevOps, QA, UI и внедрения как отдельных строк, а не «внутри fullstack».

## 3. Реализм по объёму и срокам

| Факт | Следствие для сметы |
|------|---------------------|
| ~306 пунктов карты УНФ | Оценка по **волнам и FTE**, не по «пункту меню = 1 день» |
| Ядро уже частично собрано | Остаток — не full rebuild с нуля; но глубина Э2–Э5 (СТО, МП, ЦРПТ) — почти с нуля |
| Один fullstack | Закрывает узкий поток; **не** даёт полный штат DevOps+QA+UI+внедрение за тот же календарь |
| Команда рынка 5–6,5 FTE | Полный остаток Э0–Э5 без RFID/полного Roistat: **~12 месяцев** календаря (+ буфер 1–2 мес на ключи/приёмку) |

Календарный якорь: **месяцы 1–3 / 4–9 / 10–12** (ниже). Сжатие ниже 9–10 мес без роста FTE — нереалистично при заявленной глубине.

## 5. CAPEX и ежемесячный run

### 5.1. CAPEX (поставка остатка Э0–Э5)

| Статья | Мин | Якорь | Макс |
|--------|-----|-------|------|
| **Команда FTE** (роли §4) | 18 | **21,5** | 25 |
| Аутсорс точечный (1С cutover, СДЭК/АТОЛ setup) | 0,7 | **1,2** | 2,0 |
| **Итого CAPEX** | **~19** | **~22,7** | **~27** |

В модели FTE дизайн, QA, DevOps и внедрение **уже внутри** burn команды; отдельный «пакет экранов 1,5 млн» из прежней сметы не дублируется.

Опции сверх CAPEX: RFID/ТСД **+2,2…4,0**; полный «свой Roistat» **+2,2…3,5**.

### 5.2. Run (после приёмки основных волн)

| Модель | Ориентир |
|--------|----------|
| % от CAPEX | 15–18% / год ≈ **3,0–4,0 млн ₽/год** |
| Штат run | Support L2 1,0 + DevOps 0,3 + backend 0,3 + аналитик 0,2 ≈ **0,35–0,55 млн ₽/мес** |
| Якорь run | **~0,45 млн ₽/мес** (~**5,4 млн ₽/год**) при полном контуре |

Run — инциденты, мелкие доработки, эксплуатация; не feature-бэклог Э2–Э5.

## 6. Сверка с прежней сметой и пакетом 480 тыс.

### 6.1. Смета (вкладка «Смета · роадмап ответственности»)

| Якорь в смете | Что это | Как стыкуется |
|---------------|---------|---------------|
| **~8,6 млн** | Минимум Э0–Э1+ CAPEX **6,4** + поддержка 12 мес **2,2** | Остаётся: узкий пилот склада/оплат, **без** СТО/МП/ЦРПТ |
| **~18 млн** | Прежний CAPEX полного остатка (разработка ~13 + дизайн 1,5 + аутсорс 1,2 + внедрение 2,2) | Модель **без** полного выделенного DevOps/QA/UI как FTE; занижена относительно рынка mid-2026 |
| **~21–23 млн** | Новая оценка CAPEX с полным штатом ролей + аутсорс | **Актуальный якорь** этой вкладки |

Итог: **~18 млн** — нижняя граница «лёгкой» модели; **~22–23 млн** — адекватный рынок при DevOps + UI/UX + QA + внедрение + поддержка в команде.

### 6.2. Пакет «Моё виденье» — 480 тыс. ₽/мес

| | Пакет 480 тыс. | Рыночная команда |
|--|----------------|------------------|
| Состав | **1** специалист полной занятости | **5–6,5 FTE** по фазам |
| 9 мес | **~4,3 млн** | порядка **~17 млн** burn (фазы 1–3 + часть 4–9) |
| 12 мес | **~5,5–5,8 млн** | **~21,5 млн** (+ аутсорс → **~23**) |
| Продукт | Поэтапный приоритетный поток | Паритет УНФ по глубине в календарный год |
| DevOps / QA / UI / внедрение | Внутри одного человека (ограниченная ёмкость) | Отдельные роли в ставках |

Это **разные продукты**. Сравнивать 480×12 с 22 млн CAPEX как «дорого/дёшево за одно и то же» — некорректно.

## 9. Волны (календарь)

```
Волна 0              Уже в контуре Учёта: номенклатура, остатки, sync,
                     сделки, счета/УПД, задания, ops, money UI, marking foundation
                     (вне CAPEX остатка)
        ↓
Волна 1 (мес. 1–3)   Э0 + Э1 склад/оплаты/видимость закупок
        ↓
Волна 2 (мес. 4–6)   Закупки UI, native доставка/АТОЛ, cutover bank, 2FA
        ↓
Волна 3 (мес. 6–7)   Аналитика v1
        ↓
Волна 4 (мес. 7–10)  СТО → МП
        ↓
Волна 5 (мес. 10–12) Склад Э4 (без RFID) → ЦРПТ → управленка / производство
```

**Зависимости:** native доставка ← сверки МП; партии/скан ← ЦРПТ; стабильный Э1 ← аналитика; публикация OData ← заказы поставщикам; политика устройств ← 2FA без лома операционки.

## 11. Рекомендации к переговорам

1. Якорь полного остатка с адекватным штатом ролей: **~22–23 млн ₽ CAPEX** + **~0,45 млн ₽/мес** run.  
2. Минимум Э0–Э1+: ориентир сметы **~8,6 млн** (CAPEX+год поддержки) — другой scope.  
3. Прежние **~18 млн** CAPEX — нижняя/облегчённая модель; не использовать как «полный рынок mid-2026» при выделенных DevOps/QA/UI.  
4. Пакет **480 тыс. ₽/мес** — отдельный продукт (один специалист); не подменять им командную смету.  
5. Не смешивать в одну приёмку: Э1 пилот, СТО, МП, ЦРПТ, RFID, Roistat.  
6. Блокеры Заказчика (ключи, OData, DNS, железо) — вне SLA разработки.

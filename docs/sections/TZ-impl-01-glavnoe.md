# §1. Главное — что надо для реализации

**Проект:** Учёт №1 · live `1c.pnevmopodveska1.ru`  
**Раздел каркаса:** §1  
**Оценка остатка:** S · 15–25 чел-дней остатка

---

## 1. Цель раздела

Рабочие стартовые экраны под роли (кладовщик, курьер, руководитель, СТО) и контролируемая синхронизация с 1С как часть ежедневной эксплуатации.

---

## 2. Уже есть в Учёте №1

- Начальная страница / синк 1С в UI (`/`).
- Синк справочников OData + HS; docs-sync приход/расход.
- Единый домен UI+API `1c.pnevmopodveska1.ru` (этап A).
- Ops-дашборд дня (`/ops`) как заготовка экрана руководителя по отгрузкам.

---

## 3. Можем сделать сейчас

(1–2 спринта, без новых внешних блокеров)

- Развести UX «кладовщик» (только задания/печать) от админского меню.
- Стабилизировать индикатор отставания синка (last sync / ошибки).
- Чеклист Э0: доступы, runbook, restore-drill.

---

## 4. Что надо для полной реализации

- Отдельные home-экраны: кладовщик / курьер / руководитель / СТО-выдача.
- Правила: какие документы 1С отражаются в Учёте при смене этапа сделки.
- Мониторинг синка + Telegram/алерт при отставании (см. §17).
- Приёмка: роль видит только свой контур; smoke sync < N минут отставания.

---

## 5. Блокеры / ждём

- Экраны курьера/СТО зависят от §7 и §9.
- Полный отказ от 1С как master — политика cutover (§15/Э5), не UI.

---

## 1. Цель раздела

Учёт КМ/DataMatrix по товару и партии; оборот статусов; ЦРПТ заказ/ввод/вывод/списание.

---

## 2. Уже есть в Учёте №1

- Foundation: партии, скан DM, статусы (`/marking`).
- ЦРПТ API — stub (`CRPT_*`).

---

## 3. Можем сделать сейчас

(1–2 спринта, без новых внешних блокеров)

- Дожим локального учёта марок на приёмке/отгрузке Э1 (без ЦРПТ).
- Контроль «марок vs остаток» в UI.

---

## 4. Что надо для полной реализации

- Э5: заказ КМ в ЦРПТ; ввод/вывод; списание с историей.
- Интеграция в ТСД-поток (§6) при наличии железа.
- Приёмка: скан на отгрузке обязателен для маркируемых; статусы КМ согласованы с ЦРПТ.

---

## 5. Блокеры / ждём

- Live CRPT credentials / договор.
- Стабильные партии до ЦРПТ (Э4→Э5).

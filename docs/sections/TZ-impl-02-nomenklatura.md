# §2. Номенклатура — что надо для реализации

**Проект:** Учёт №1 · live `1c.pnevmopodveska1.ru`  
**Раздел каркаса:** §2  
**Оценка остатка:** S · 10–20 чел-дней

---

## 1. Цель раздела

Полный учёт карточек товара: применимость, характеристики, виды цен, бренды, фото S3, штрихкоды — с историей изменений.

---

## 2. Уже есть в Учёте №1

- Каталог, категории, бренды, цены, применимость (марки/модели) — sync + UI.
- Медиа → S3 (FirstVDS); coverage API.
- Остатки связаны с номенклатурой через HS Get/Rests.

---

## 3. Можем сделать сейчас

(1–2 спринта, без новых внешних блокеров)

- Polish карточки (пустые характеристики, виды цен в одном экране).
- Штрихкоды/артикулы: проверка отображения и поиска.
- Связь «история товара» с приходами (цены закупа из §4).

---

## 4. Что надо для полной реализации

- Редактирование master в Учёте vs read-only из 1С — явное решение.
- Полный набор доп. параметров/характеристик как в 1С.
- Массовые операции (цены, категории).
- Приёмка: карточка = применимость + ≥1 вид цены + фото; поиск по артикулу/ШК.

---

## 5. Блокеры / ждём

- Cutover master-номенклатуры из 1С — бизнес-решение, не код спринта.

---

## 6. Зависимости

См. сводную таблицу и волны на вкладке «Роадмап · можем сейчас». Детали смежных разделов — вкладки § соседних номеров.

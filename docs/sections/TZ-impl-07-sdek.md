# §7. Доставка / СДЭК — что надо для реализации

**Проект:** Учёт №1 · live `1c.pnevmopodveska1.ru`  
**Раздел каркаса:** §7  
**Оценка остатка:** M · 25–45 чел-дней

---

## 1. Цель раздела

Создание накладной, трек и ярлык из Учёта; каналы доставки; экран курьера.

---

## 2. Уже есть в Учёте №1

- Внешний виджет СДЭК (`CDEK_WIDGET_URL` → `deal.php`) — оформление накладной (карта ПВЗ, тарифы).
- Native API СДЭК **на виджете**: OAuth `client_id`/`client_secret` по 3 кабинетам (Мск / Стрела / Фогель), статус API `ok` (проверено 2026-07-19).
- Machine bridge WMS→виджет: `GET/POST …/cdek/wms_api.php` + в Учёте `GET /warehouse/tasks/:id/cdek`, `POST …/cdek/sync` — трек, статус, ярлык PDF в задании.
- Каналы в заданиях склада (предоплата/наложка/самовывоз/автобус и т.д.).

---

## 3. Можем сделать сейчас

(1–2 спринта, без новых внешних блокеров)

- Пилот: кладовщик оформляет в виджете → «Подтянуть трек» в задании → ярлык PDF.
- Поля вес/габариты в карточке задания (ввод если пусто).

---

## 4. Что надо для полной реализации

- E1-7: создание накладной **прямо из Учёта** (без UI виджета) — опционально; сейчас native уже через виджет + sync.
- Экран курьера (отдельно от кладовщика).
- Прочие ТК по тому же контракту при необходимости.

---
